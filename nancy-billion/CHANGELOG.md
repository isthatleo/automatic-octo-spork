# Changelog

## 2026-08-06 — Knowledge Engine: the first real Phase IV work (Book II)

- **New `backend/knowledge/` package**: a persisted entity/relationship graph (`graph.py`) plus grounded LLM extraction (`extraction.py`), composing two subsystems that were already real -- memory's embeddings and `doc_extraction.py`'s PDF/DOCX text -- into a third that didn't exist. Confirmed via audit against Book II's 20-phase roadmap that Phase IV (Knowledge Engine) was the most tractable real gap: Memory (Phase III) and Document Intelligence (Phase V) already produced grounded, embedded content, but nothing resolved entities ("Leonard," "OANDA," "EUR/USD") into linked knowledge.
- **The honesty mechanism**: `memory/wiki_store.py` had already explicitly declined to build "generative entity/concept clustering," calling it open-ended NLP rather than a fixed, testable deliverable. This is the grounded version of that same feature: every entity and relationship an LLM proposes must carry an `evidence_quote`, and `quote_is_grounded()` rejects any candidate whose quote isn't an actual, verbatim substring of the source text. A model can still miss things or mistype a type, but it cannot hallucinate an entity into the graph without also hallucinating a quote that would need to match real text character-for-character. Relationships are further constrained to only reference entities that themselves survived grounding.
- Six entity types (person/organization/project/technology/concept/document) and Book V Ch.7's exact ten relationship types (supports/contradicts/depends_on/inspired_by/created_by/uses/built_with/extends/derived_from/related_to). Entity resolution merges on exact name/alias match, then difflib near-duplicate spelling match (deliberately not the sentence-transformers embedding model memory/graph.py uses -- catches "OANDA"/"Oanda" without needing that model loaded, at the honestly-documented cost of not catching true synonyms). Confidence is capped by `trust.py`'s existing `CONFIDENCE_CEILING` for `provenance="retrieved"`, the same ceiling discipline the memory graph already enforces.
- Extraction reuses `llm_task.structured_llm_call` (schema validation + one retry on bad JSON) rather than hand-rolling prompt/parse logic -- no new LLM-calling code path was added.
- Wired as two real chat tools (`extract_knowledge`, `search_knowledge_graph`, both added to `_all_chat_tools()` and the tool-executor dispatch) and four REST routes (`GET /knowledge/graph`, `GET /knowledge/search`, `GET /knowledge/entity/{name}`, `POST /knowledge/extract`), matching the existing `/memory/wiki` route shape (auth + rate-limit dependencies, a `BaseModel` request type).
- `backend/tests/test_knowledge_graph.py`: 11 dependency-light tests (no network, no LLM, no model load) covering entity merge/alias/type-scoping, relationship dedup, persistence round-trip, confidence ceiling enforcement, and the grounding-check function itself. All pass; the pre-existing `test_trust_conformance.py` suite (8 tests) still passes unchanged.
- Scope note: this is Phase IV started, not finished -- no auto-triggering on every memory write or document extraction (kept explicit/opt-in to avoid surprise LLM cost/latency), no cross-document contradiction detection beyond what `wiki_store.py` already does for wiki pages, no UI. Extraction quality itself (what the LLM chooses to report, not whether it's grounded) is not covered by these tests, matching `test_trust_conformance.py`'s own stated scope boundary.
- Books I-V of the NÅNCY canonical specification saved to `docs/canon/` as the living reference for future phase work. Book III's Rust/Axum/monorepo architecture is treated as long-term aspirational guidance, not an active migration -- the audit against Book II confirmed substantial real, working functionality in the current Python/FastAPI backend (80 routed specialized agents, genuine agent-to-agent peer review, the memory graph, live TradingView wiring) that a literal rewrite would have discarded.

## 2026-07-30 — Apps for all five platforms, and a picked model that actually holds the tools

- **Picking a model no longer stops mattering the moment you ask for something.** `TOOL_FALLBACK_BACKENDS` only listed OpenRouter, Groq and OpenCode, so choosing OpenAI, Ollama Cloud or a local Ollama model as primary looked like it worked — plain replies came back from the picked model — while every *tool-using* turn silently fell through to Claude. The three missing providers are now first-class tool backends (Ollama Cloud via its OpenAI-compatible `https://ollama.com/v1`, local Ollama via `OLLAMA_BASE_URL` + `/v1`), key resolution accepts `OLLAMA_API_KEY` (the name Ollama's own CLI writes) as well as `OLLAMA_CLOUD_API_KEY`, `OllamaAutoModelsLLM` is aliased to `OllamaLLM` so a local daemon matches whichever way the chain built it, and the loop logs which backend it actually chose. Covered by `backend/test_tool_backend_order.py`, which lifts the real routing source out of `main_new.py` rather than re-implementing it, so edits to the routing are seen by the test. 17 checks, green on-device.
- **Five app targets, one command each.** `scripts/build-apps.ps1` (Windows) and `scripts/build-apps.sh` (macOS/Linux) install dependencies, package, and open the right IDE: Electron produces an NSIS installer + portable exe, a `.dmg`, and AppImage + `.deb`; Capacitor generates the Android and iOS projects, applies the icon set, and opens Android Studio or Xcode ready to hit Run. Preflight checks for Node 18+ and refuses iOS anywhere but macOS instead of failing halfway through.
- **The mobile apps find your machine by themselves.** `capacitor.config.json` had a hardcoded `192.168.1.100`, which was wrong for everyone and broke on every network change. The app now ships a shell that tries the last known host, then the emulator loopbacks (`10.0.2.2`, `localhost`), and only asks if none answer — remembering the answer thereafter and assuming port 3005 for a bare address. Verified headlessly against Chromium: falls back to the prompt, connects to a typed host, remembers it across relaunch, normalises bare addresses.
- **iOS ATS exception applied automatically** (`mobile/scripts/patch-native.js`): the control room is plain http on a LAN, which iOS blocks by default and Capacitor doesn't patch for you. Runs idempotently on every `cap sync`.
- **Icons are generated, not hand-drawn** (`scripts/gen_icons.py`): one procedural definition of the reactor mark renders the desktop icon at 1024 (electron-builder rejected the old 256), the web/PWA set with a properly padded maskable variant, and the 1024 mobile icon + 2732 splash that `@capacitor/assets` expands to every density.
- **PWA install path documented as the zero-build option** — the manifest added the previous day makes the control room installable as a real windowed app on all five platforms straight from the browser, which is enough for most day-to-day use. Full guide in `docs/APPS.md`.

## 2026-07-29 — Context bridge, Claude capability wiring, procedural memory, voice fallback

- **Context bridge made real end-to-end** (was silently dead): frontend route read `NANCY_BACKEND_BASE_URL` (never set anywhere) so inside Docker it forwarded to the frontend container's own localhost — the exact silent-502 class of bug the README documents. Now reads `BACKEND_URL` first. Nothing in the UI ever POSTed context at all; the dashboard now reports `active_panel`/`speaking`/`thinking` on change plus a 10s heartbeat, with schema fields, a 3s forward timeout, rate-limiter pruning, and a 60s backend staleness guard so a dead dashboard's `speaking=True` can never haunt the system prompt hours later (`get_live_context_snapshot`).
- **Full modern Claude wiring** (`llm.py`): real system role (`_anthropic_system_blocks`) with **prompt caching** on the static persona block and the tool-schema array — previously the whole persona+skills+memory text was concatenated into the user message and re-billed at full input price on every round of every tool loop. Applied to all three Claude paths (chat tool loop, streaming chat, cron/webhook skill runs) via `_build_chat_parts`' static/dynamic/user split; single-string prompt kept byte-identical for the OpenAI-compat fallbacks. Also added real vision input (`images=` on `generate()`).
- **Skill distillation loop** (Hermes-style solve → distill → reuse): tool-using turns now record a real tool trace; a turn taking ≥2 tool calls with no existing skill match triggers a background distillation pass (Claude drafts a SKILL.md; Telegram approval required; `skill_loader.save_skill()` hot-registers with no restart). Never adds latency to the reply, never overwrites an existing skill, discards silently on rejection.
- **Verbatim conversation recall** (`conversation_log.py`): SQLite **FTS5** log (porter stemming) of every real chat turn, populated at the same chokepoint as the memory graph plus the streaming path. New `search_conversation_history` chat tool and `GET /memory/conversations/search` — exact-text recall with snippets, complementing semantic `/memory/search`. Degrades to honest no-ops if FTS5 is unavailable. Live-tested (stemmed match confirmed).
- **Server-side STT fallback** for browsers without the Web Speech API (Firefox/Safari): new `POST /voice/transcribe` (auth+rate-limited, size-capped) decoding the same WebM/Opus format `voice-capture.ts` produces through faster-whisper; Next proxy route; `use-voice.ts` fallback loop records 5s segments from one shared stream, drops silent segments client-side via a real level meter, and feeds transcripts into the same wake-word pipeline. The transcribed segment doubles as the voice-ID sample. Chrome path untouched.
- **Agent honesty badges in the UI**: fleet roster cards + detail modal now surface each agent's real `mode`/`hardware_connected` flags (`SIMULATED`, `HYBRID`, `SIM · NO HW`) — the frontend half the 2026-07-12 honesty audit called for.
- **Per-panel error boundary** (`panel-error-boundary.tsx`): a crashing panel now shows a retry card naming the panel instead of blanking the whole control room; `key={panel}` resets it on navigation.
- Repo hygiene: 13 stray backup/log/corrupted files moved to `_to_delete/` (sandbox can't delete on-device; remove that folder at leisure), `.gitignore` updated. Swarm-coordinator "not real delegation" changelog note from 2026-07-12 verified **outdated** — `swarm_execute` now genuinely routes through `agent_service`.
- Full audit + prioritized roadmap in `docs/UPGRADE_AUDIT_2026-07-29.md` (sub-repo wiring table, Hermes/OpenClaw adoption list, frontend review, JARVIS roadmap).

## 2026-07-12 — Phase 2: honesty audit of the 9 "advanced enhancement" agents

All 9 agents from TODO.md's ask (`artificial_consciousness_core`, `recursive_self_improvement_engine`, `ethical_governance_core`, `embodied_cognition_interface`, `temporal_prediction_engine`, `multi_agent_swarm_coordinator`, `quantum_reasoning_accelerator`, `neural_interface_agent`, `holographic_display_controller`, `environmental_control_nexus`) already existed (300-1400 lines each, registered, reachable via real `/agents/*` REST endpoints) — this pass audited each for honesty and safety rather than building from scratch:

- **`artificial_consciousness_core.py`** — real computation (Shannon entropy, KL-divergence, Bayesian updates, IIT-style Phi), but the docstrings/interpretation strings explicitly claimed actual sentience ("rich internal experience," "qualia-simulation" as a listed API capability, "Strong candidate for sophisticated conscious experience"). Rewrote all of it to honestly describe real introspection/metacognition metrics without claiming subjective experience, while keeping the underlying math unchanged.
- **`recursive_self_improvement_engine.py`** — confirmed it has zero filesystem/subprocess/exec access (cannot touch real code) and already had an automated `SafetyVerifier` gate, but no human-in-the-loop step — a caller could chain propose→verify→apply autonomously. Added a required `human_approve` step (with an `approved_by` identifier) between automated verification and `apply`.
- **`ethical_governance_core.py`** — found and removed a circular fake-confidence bug: Gaussian noise was added "to simulate deliberation uncertainty," then confidence was derived from that same synthetic noise. Replaced with a real signal (confidence scales with how clear-cut the aggregate score is).
- **`neural_interface_agent.py`, `holographic_display_controller.py`, `environmental_control_nexus.py`** — all three advertised real hardware integration (EEG headset SDKs, light-field displays, smart-home hubs) in their `capabilities`/`tools` fields and returned `"success"`/`"status": "success"` responses indistinguishable from real hardware actuation, with no Provider/Mock abstraction anywhere. Added explicit `mode: "simulated"` / `hardware_connected: false` flags, split "tools actually used" from "designed for future integration with," and relabeled response fields (e.g. `devices_affected` → `devices_that_would_be_affected`) so simulated results can never be mistaken for real hardware output.
- **`temporal_prediction_engine.py`** — the `model` field on each forecast (e.g. "LSTM", "Prophet") was chosen by `random.choice` and never actually influenced the computation (always linear-trend + Gaussian noise) — documented this explicitly rather than implying a specific algorithm ran.
- **`multi_agent_swarm_coordinator.py`** — confirmed it does NOT delegate to the system's other 28 real agents (purely internal simulated state); added an explicit docstring disclaimer pointing to `agent_service.py` as where real routing actually happens.
- **`quantum_reasoning_accelerator.py`** — re-verified already honest (explicit "classically simulated" disclaimers throughout); no changes needed.
- Added `mode`/`hardware_connected` fields to `base_specialized_agent.py`'s `get_info()` (used by `/agents/list`) so the frontend can badge simulated vs. production agents in the roster view, not just the per-agent detail view.
- Wired Claude specifically into coding/self-improvement/devops task routing: `select_llm_for_task()` now also matches those hints, and `main_new.py`'s `/chat` endpoint requests `effort="high"` (adaptive thinking) from `claude-opus-4-8` specifically for those task types.

## 2026-07-12 — CRITICAL FIX: backend/tools.py could not be imported at all

While running a final full-backend compile check (`python -m compileall`), discovered `backend/tools.py` — imported unconditionally at the top of `main_new.py` (`from tools import get_tools`) — was missing its entire header: no `logger`, no `add_tool()` function, no `get_tools()` function. Only ~630 lines of `add_tool(...)` call sites remained, plus null-byte corruption and mixed `\r\r\n`/`\r\n` line endings. **This meant `main_new.py` could not be imported, and the backend could not start, independent of any change made in this session** — confirmed pre-existing by checking `git show HEAD:nancy-billion/backend/tools.py` (same corruption already present in the last commit).

Fixed by: normalizing all line endings to `\n`, removing stray null bytes, fixing 13 instances of a double-escaped-quote corruption (`\\'` → `\'`, e.g. `'or \\'all\\'' ` broke string parsing), and reconstructing the missing `add_tool`/`get_tools`/`logger` header. The reconstruction is grounded in verified evidence, not guesswork: every `add_tool(id, description, execute, input_schema, output_schema)` call site uses the exact 5-positional-argument shape of `fury.types.create_tool()` (confirmed by reading `fury-main/src/fury/types.py`, the source for the `fury-sdk` dependency), so `add_tool` is a thin wrapper appending a `Tool` to a module list, and `get_tools()` returns that list. Also fixed the same UTF-16/null-byte corruption in the unrelated, unused `agents/test/test_agent.py` fixture. Full backend now passes `python -m compileall` with zero errors — verified end to end, not just for the files touched this session.
